# ヘルプとチュートリアルの設計(v0.1)

更新日: 2026-11-08
状態: 採用(ユーザー決定2026-11-08)。「使い方」と機能ヘルプはこの文書を正とする。7章の3段すべてを実装済み(2026-11-08)。

## 1. 問題

現在の「使い方」(`src/components/ide/help-dialog.tsx`)は12項目の説明を1枚のダイアログに一度に並べる。

- **今の画面と結び付かない。** 仕分けボードや「条件を変える」のように、そのステップでは画面に出ていない機能も混ざる。初学者は「どれのことか」を探しながら読むことになる。
- **機能が増えるたびに伸びる。** Issue #36で2項目を足したように、課題の種類や結果ペインの機能が増えると項目が線形に増える。
- **説明が機能から離れている。** 「帳簿をさかのぼる」のスライダーが何かを知りたいとき、右上の「使い方」を開き、一覧から該当項目を探す。
- **初めて出る課題の種類に案内が無い。** 「予想して記帳する」「条件を変える」は最初の単元に出ないので、チュートリアルでは触れられない。初めて現れたステップで、その場の説明だけで理解する必要がある。
- **文言が2か所にある。** 同じ機能の説明が`help-dialog.tsx`と`tutorial-tour.tsx`に別々に書かれ、片方だけ直ると食い違う(Issue #20はツアー側で起きた)。

## 2. 考え方

1. **段階的に開示する。** いちばん近くに1文、押せば1〜3文、「使い方」で2〜4文、通しで学ぶならツアー。読む量は学習者が選ぶ。
2. **説明は機能の隣に置く。** 説明を読みに行く場所を増やさず、疑問が湧いた場所で答える。
3. **「いまの画面」を先に出す。** 「使い方」は、現在のステップで画面に出ている機能を最初に、残りは分類ごとに畳んで出す。
4. **文言は1か所に持つ。** 機能ヘルプ・初出の案内・「使い方」は同じ表(4章)から文言を引く。ツアーは操作の台本なので別に持つが、機能名と用語はこの表に合わせる。
5. **読ませるより触らせる。** 説明には「場所を示す」のような行動を付け、読んだあとに画面へ戻れるようにする。IDEの原則(ide-design.md 1章)と同じ。

### 参考にしたもの

| 参照 | 取り入れる | 取り入れない |
|---|---|---|
| Codecademyの学習画面 | 困ったときの手がかりを課題の隣に置く(Get Unstuckはガイドの中にある)。初回だけの短いツアーで画面の役割を覚える | コミュニティ投稿やAIによる回答(M1では実LLMを呼ばない) |
| VS CodeのWalkthrough(Get Started) | 手順は学習者の操作で完了する(既存ツアーと同じ。ボタンを押す段は押せば次の段へ進み、入力の段は完了を示してカードの「次へ」で進む)。いつでもHelpから戻れる。新しい機能は初回だけ軽く知らせる(通知バナー) | 全機能にWalkthroughを用意する(保守が重く、流れを切る) |
| VS Codeの設定画面 | 各項目の横の小さな(i)で、その項目だけの説明を読む | ホバーだけで出るツールチップ(タッチで出ず、キーボードで読みにくい) |

## 3. 4つの層

| 層 | 名前 | 出るとき | 中身 | 持つ状態 |
|---|---|---|---|---|
| 0 | その場の文言 | 常に | 1文(既存: 「借方と貸方の合計をそろえると記帳できます」) | なし |
| 1 | **機能ヘルプ** | 学習者が見出し横の「?」を押したとき | 題 + 1〜2文 + 「もっと詳しく」 | なし |
| 2 | **初出の案内** | 新しい課題の種類が初めて画面に出たとき | 題 + 1〜2文 + 「わかった」「くわしく」 | 見た課題の種類 |
| 3 | **使い方** | ヘッダーの「使い方」 | 「いまの画面」+ 分類ごとの折りたたみ + チュートリアルと設定 | なし |
| 4 | **操作ツアー** | 初回と、やり直し | 既存のまま(`tutorial-tour.tsx`) | 未実施 / スキップ / 完了 |

層1〜3は同じ「ヘルプの話題」(4章)を描き分けたもの。層4は1件記帳する台本で、話題の表とは独立。

## 4. ヘルプの話題(単一の正本)

`src/lib/help-topics.ts`に表として持つ。コンポーネントは文言を直接書かず、この表を参照する。

```ts
interface HelpTopic {
  id: string;                 // "journal" / "impact" / "rewind" …
  category: "guide" | "work" | "result" | "task" | "progress";
  title: string;              // 「帳簿をさかのぼる」
  short: string;              // 機能ヘルプと初出の案内。1〜2文
  body: string | ((ctx: HelpContext) => string); // 「使い方」。2〜4文。手順と、キーボードの別手段。課題の種類で言えることが変わる話題は関数
  target?: string;            // data-tourの値。「場所を示す」で光らせる
  pane?: "guide" | "work" | "result";
  when?: (ctx: HelpContext) => boolean; // 「いまの画面」に入れる条件。無ければ常に
}
interface HelpContext {
  taskType: TaskType;         // 現在のステップの課題の種類
  postedCount: number;        // 記帳済みの件数(さかのぼるは2件以上で出る)
  isLast: boolean;            // 最後のステップ(自由に試す)
}
```

### 4.1 話題の一覧

| id | 分類 | 題 | 「?」を置く場所 | 初出の案内 | いまの画面の条件 |
|---|---|---|---|---|---|
| guide | ガイド(読む) | ガイドの読み方 | 置かない(ツアーで扱う) | – | 常に |
| hint | ガイド | ヒントと答え | 「ヒントを見る」の横 | – | ヒントがある課題 |
| journal | ワークスペース(書く) | 仕訳帳に書く | 見出し「仕訳帳に書く」の横 | – | post / 自由に試す |
| impact | ワークスペース | 影響の表示 | 影響の行の横 | – | post / predict / 自由に試す |
| posted | ワークスペース | 記帳済みの一覧 | 置かない(見れば分かる) | – | 常に |
| ledger | ワークスペース | 総勘定元帳(T勘定) | タブ列の右端 | – | 常に |
| statements | 結果(見る) | 貸借対照表と損益計算書 | 見出し「貸借対照表」の横 | – | 常に |
| shape | 結果 | 会社のかたち | 帯の右上 | – | 記帳が1件以上 |
| rewind | 結果 | 帳簿をさかのぼる | ラベルの横 | – | 記帳が2件以上 |
| changed | 結果 | このステップで動いた要素 | 置かない(見出しが説明になっている) | – | 動いた要素があるとき |
| predict | 課題の種類 | 予想して記帳する | 見出し「記帳すると…」の横 | ○ | predict |
| classify | 課題の種類 | 箱に分ける | ボードの見出しの横 | ○ | classify |
| calc | 課題の種類 | 金額で答える | 入力欄の見出しの横 | ○ | calc |
| tweak | 課題の種類 | 条件を変える | 目標の見出しの横 | ○ | tweak |
| sandbox | 課題の種類 | 自由に試す | 見出し「自由に試す」の横 | ○ | 最後のステップ |
| steps | 進め方 | ステップと「次へ」 | 置かない | – | 常に |
| resume | 進め方 | 続きから | 置かない | – | 常に |

resumeは2つの戻り方を説明する。同じタブで単元を離れて戻ったとき(ブラウザの戻る、reload、他のページから開き直す)は、離れる前のステップと入力途中の答え(仕訳、予想、配置、金額、条件)を`sessionStorage`から戻し、「続きから」は出さない(Issue #83)。タブを閉じたあとはDBの進捗から「続きから」を出す。チュートリアル単元はツアーがステップ1からの台本なので、同じタブでも「続きから」に任せる。

### 4.2 文言の規則

- `short`は「何ができるか」を動詞で終える1文と、操作を1文。「結果の上のスライダーで、記帳を1件ずつ巻き戻せます。動かすと、その時点の会社の姿になります。」
- `body`は`short`に、キーボードの別手段と、つまずきやすい点を足す。4文まで。
- 専門用語は使う前に本文の単元で定義されているものに限る。説明の中で新しい用語を導入しない(新しい用語は単元の`introduces`の責務)。
- 「〜してください」ではなく「〜できます」「〜してみましょう」(ide-design.md 5章の文体)。

## 5. 各層の仕様

### 5.1 機能ヘルプ(「?」)

```
 仕訳帳に書く ⓘ          ← 見出しの右に 16px のアイコン。押すとポップオーバー
                          ┌──────────────────────────────┐
                          │ 仕訳帳に書く                 │
                          │ 科目と金額を入れて「記帳する」│
                          │ を押します。科目は途中まで打つ│
                          │ と候補が出ます。             │
                          │ もっと詳しく →               │
                          └──────────────────────────────┘
```

- **見た目**: Lucide `CircleHelp` 16px、`text-muted-foreground`、ホバーとフォーカスで`text-foreground`。見出しの行高を変えないよう、押せる範囲は32px四方(`size="icon-sm"`相当)で負のマージンを使う。状態色・要素色は使わない。
- **開閉**: クリック / タップ / Enterで開く。ホバーでは開かない(用語ポップオーバーはホバーで開くが、こちらは本文ではなくUIの部品なので誤開を避ける)。Escで閉じ、フォーカスは「?」に戻る。既存の`Popover`(`src/components/ui/popover.tsx`)を使う。
- **aria**: `aria-label="「仕訳帳に書く」の説明"`。ラベルに「使い方」を含めない(ヘッダーの「使い方」ボタンを名前で探すテストとMonkeyに部分一致で当たる)。ポップオーバーは`aria-label`に題を持つ。
- **中身**: 題、`short`、「もっと詳しく」(押すと「使い方」をその話題を開いた状態で表示)。それ以上は置かない。
- **置く場所の規則**: 1つの見出しに1つまで。1ペインに同時に出るのは3つまで。ボタン・入力欄・ガイド本文には置かない(ラベルと層0の文言で足りるべき)。表4.1の「置かない」は、このルールで落としたもの。
- **ツアー中は出さない。** ツアーのスポットライトと重なって2つの説明が同時に見えるのを避ける。

### 5.2 初出の案内

```
┌ ワークスペース ──────────────────────────────────────────┐
│ ┌────────────────────────────────────────────────────┐   │
│ │ 初めての「予想して記帳する」                        │   │
│ │ 記帳の前に、5 要素がどう動くかを選びます。外れても  │   │
│ │ 実際の動きと見比べて進めます。   [くわしく] [わかった]│   │
│ └────────────────────────────────────────────────────┘   │
│ これから記帳する仕訳 …                                    │
```

- **出す条件**: 課題の種類がpredict / tweak / classify / calc / debug / 最後のステップの自由に試す のいずれかで、その種類をこのブラウザで初めて見たとき。チュートリアル単元では出さない。ツアー中は出さない。再開時に既に結果が出ているステップでも出さない。
- **出し方**: ワークスペースの先頭に、既存の「初めてですか?」バナーと同じ見た目(`border-primary/30 bg-primary/5`、`role="note"`)。モーダルにせず、フォーカスも奪わない。スポットライトも使わない(ステップの説明がすぐ下にあり、暗くする相手がいない)。
- **消える条件**: 「わかった」を押す、または、その課題で「確認する」「予想して記帳する」などを押して結果が出る。どちらでも見た扱いにする。
- **同時に1つ**。別のバナー(初めてですか? / 続きから)があるときは、それらの後に出す。
- **なぜツアーにしないか**: 課題の種類ごとに台本を書くと5本のツアーを保守することになり、ステップの流れも切れる。まず案内1枚で試し、Monkeyと手動テストで迷いが残る種類だけ「場所を示す」(5.3)を1段付ける。

### 5.3 「使い方」

```
┌ 会計 IDE の使い方 ─────────────────────────────────── × ┐
│ 困ったときに、必要なところだけ開いて読めます。            │
│                                                         │
│ いまの画面でできること   ステップ 4「予想して記帳する」  │
│   予想して記帳する ─ 記帳の前に、5 要素が… [場所を示す]  │
│   影響の表示 ─ 入力中の仕訳で…            [場所を示す]  │
│   帳簿をさかのぼる ─ 結果の上のスライダーで… [場所を示す]│
│                                                         │
│ すべての機能                                            │
│   ▸ ガイド(読む)                               2 項目  │
│   ▸ ワークスペース(書く)                       4 項目  │
│   ▸ 結果(見る)                                 4 項目  │
│   ▸ 課題の種類                                 5 項目  │
│   ▸ 進め方                                     2 項目  │
│                                                         │
│ チュートリアルと設定                                     │
│   [チュートリアルを最初から]                             │
│   □ 初めて単元を開いたときにチュートリアルを案内する      │
└─────────────────────────────────────────────────────────┘
```

- **いまの画面でできること**: `when(ctx)`が真の話題を、ガイド → ワークスペース → 結果の順で最大5件。常に展開。見出しの右に現在のステップ番号と課題の種類を添え、「どの画面の話か」を固定する。
- **すべての機能**: 分類ごとの折りたたみ。HTMLの`<details>` / `<summary>`を使い、新しい依存を足さない。`summary`は44pxの高さで、題と項目数を出す。中は題(`dt`)と`body`(`dd`)の定義リスト。
- **話題を指定して開く**: 機能ヘルプの「もっと詳しく」と初出の案内の「くわしく」は、その話題の分類を開き、話題へスクロールしてフォーカスを移す(`id="help-<id>"`)。閉じたらフォーカスは押した「?」や「くわしく」へ戻す。
- **場所を示す**: `target`を持つ話題に付く。押すとダイアログを閉じ、スマートフォンでは`pane`へ切り替え、対象をツアーと同じリング + 暗幕で3秒間、または何か操作するまで光らせる。ツアーの`useTargetRect`と暗幕の描画を1段だけのツアーとして再利用する。対象が画面に無い(その課題の種類でない)話題には付けない。
- **チュートリアルと設定**: 既存の2つを末尾に移す。先に機能説明、最後に設定。
- **スマートフォン**: 既存どおり高さ85dvhでスクロール。折りたたみにより初期表示は1画面に収まる。

### 5.4 操作ツアーとの関係

- ツアーは1件記帳する台本で、変えない。ツアーの11段目「困ったら使い方」の文を「右上の『使い方』と、見出し横の ? で、いつでも説明を読めます」に改め、層1の存在を知らせる。
- ツアーの各段の題(「ここはガイド」「影響がその場で見える」…)で使う機能名は、話題の`title`と同じ語にそろえる。

## 8. アクセシビリティと操作

- 「?」は`button`。可視のフォーカスリング、Escで閉じる、閉じたらフォーカスを戻す。ホバー専用の情報を作らない。
- 初出の案内は`role="note"`。`aria-live`は付けない(ステップが変わったときの読み上げと重なる)。
- 「使い方」の折りたたみはネイティブの`summary`なので、TabとEnter / Spaceで開閉できる。
- 「場所を示す」の暗幕はツアーと同じく`pointer-events: none`。`prefers-reduced-motion`ではリングの移動アニメーションを切る。
- 色はテーマのトークンだけを使う(design-system.md)。「?」は`--muted-foreground`、案内の面は`--primary`の淡い面。ヒントの状態色は使わない(ヒントは課題の手がかり、案内は操作の説明で役割が違う)。

## 9. 検討した別案

- **全文検索付きのヘルプ**: 話題は20件に満たず、検索窓は分類の折りたたみより迷わせる。不採用。
- **独立したヘルプページ(`/help`)**: IDEを離れると「どの部品のことか」が切れる。ダイアログ内で完結させる。公開ページは、用語集のように後で必要になったら話題の表から生成する。
- **`title`属性やTooltipで済ませる**: タッチで出ず、スクリーンリーダーでの扱いもまちまち。「?」ボタン + Popoverに統一する。
- **課題の種類ごとの個別ツアー**: 5.2のとおり保守が重い。案内1枚から始める。
- **初回に全機能を通すツアーへ拡張**: 12段でも長いという前提(2分)を崩す。初出の案内に分散させる。
- **AIチャットによるヘルプ**: M1では実LLMを呼ばない。採点と解説はコンテンツで完結させる境界(CLAUDE.md)とも合わない。
- **動画**: 画面が変わるたびに撮り直しになる。図解はコードで描く方針(ADR 0004)にも合わない。
