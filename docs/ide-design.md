# 会計IDEの設計(v0.1)

更新日: 2026-11-07
状態: 採用(ユーザー方針2026-11-07)。画面と学習フローはこの文書を正とし、縦スライスを作り替えて検証する。

## 1. コンセプト

**コードを書いて実行しながらプログラムを理解するように、仕訳を切って「実行」しながら会計を理解する。**

Codecademyの学習画面は「左に短い説明と課題、中央にエディタ、右に実行結果」で、学習者は読む時間より手を動かす時間のほうが長い。
会計でこれに相当するのは:

| プログラミング学習 | 会計IDE |
|---|---|
| 課題の説明と手順(左) | 小さな会社の物語と「やること」(左: ガイド) |
| コードエディタ(中央) | 仕訳帳。勘定科目と金額を入れて仕訳を組み立てる(中央: ワークスペース) |
| 実行 → 出力(右) | 記帳 → 貸借対照表と損益計算書が動く(右: 結果) |
| テストが通る / 失敗して差分が出る | 期待どおりの財務諸表になる / 何がどう違うかが視覚的に出る |
| 変数を変えて再実行 | 金額・耐用年数などの条件を変えて財務諸表の変化を見る |
| 1レッスン = 複数の小さな課題を順に | 1単元 = 1つの会社の数日〜1か月を、6〜10ステップで追体験する |

長い解説を読んでから問題を解くのではなく、**ステップごとに「短い説明 → 操作 → 結果の確認 → 次へ」** を繰り返す。
専門用語は操作の直後に名前を与える(「いま入力した左側を借方と呼びます」)。本文中の用語はこれまで通りポップオーバーで段階的に掘れる。

## 2. 画面構成

### 2.1 PC(幅1024px以上)

```
┌──────────────────────────────────────────────────────────────────────────────────┐
│ 5 つの要素と仕訳   ●●●●○○○○  ステップ 4 / 8                        [用語集]      │
├───────────────────────┬──────────────────────────────┬───────────────────────────┤
│ ガイド                │ ワークスペース               │ 結果                      │
│                       │  [仕訳帳] [条件を変える]     │  [貸借対照表] [損益計算書] [影響] │
│ カフェの開店 2 日目。 │                              │                           │
│ コーヒーマシンを      │  借方          │ 貸方        │  貸借対照表 (4/2 時点)     │
│ 300,000 円で買い、    │  [備品  ][300,000]│[現金][300,000]│  資産            負債     │
│ 代金は現金で払いました│  [+ 行を追加]  │ [+ 行を追加]│   現金   700,000 ▼300,000 │
│                       │                              │   備品   300,000 ▲300,000 │
│ ▶ やること            │  資産 ±0 負債 ±0 純資産 ±0   │              純資産        │
│ この取引を仕訳して    │  収益 ±0 費用 ±0 利益 ±0     │   資本金 1,000,000        │
│ 記帳しましょう        │  借方 300,000 / 貸方 300,000 │  ──────────────────────   │
│                       │               [記帳する]     │  損益計算書 ...           │
│ ヒントを見る          │                              │                           │
│                       │  記帳済み                    │  (変わった行は色と▲▼で   │
│                       │  4/1 現金 1,000,000/資本金   │   強調。前のステップとの  │
│                       │      1,000,000               │   差分)                   │
├───────────────────────┴──────────────────────────────┴───────────────────────────┤
│ ✓ 記帳できました。現金が減って備品が増え、資産の合計は変わりません。     [次へ →] │
└──────────────────────────────────────────────────────────────────────────────────┘
```

- **ガイド**(左1/3): 現在のステップの物語(短い説明)、「やること」、ヒント。読む量を小さく保つ。末尾に「誤りを報告」「この単元を改善」のテキストリンク(GitHubを新しいタブで開く)。
- **ワークスペース**(中央1/3): 仕訳帳。記帳済みの仕訳が下に積まれ、学習者の会社の帳簿が育っていく。
  ステップの種類によって「条件を変える」(数値のスライダー)や「仕分けボード」(科目を5つの箱に入れる)に切り替わる。
- **結果**(右1/3): 貸借対照表と損益計算書。記帳のたびに更新され、変わった行を強調し、前のステップとの差分(▲▼)を出す。
  「影響」タブは5要素の増減をバーで見せる。
- **フィードバック**(下): 確認結果。不正解のときは「あなたの仕訳がもたらす影響」と「期待される影響」を並べ、どの要素がどれだけずれたかを示す。
  誤解が検出されたら、その誤解の説明と、解きほぐすステップへのリンクを添える。案内先がいまの単元を前提にしている単元なら、リンクにせず「あとの単元で学ぶ」と文で伝える。

### 2.2 スマートフォン
縦積み。上部に[ガイド | ワークスペース | 結果]のタブ、下部に固定の操作バー(記帳する / 確認する / 次へ)。
「確認する」のあとは自動で結果タブに切り替えて変化を見せる。
タブ表示の幅(1024px未満)では、ガイドが隠れても問題を確かめられるよう、仕訳・予想のステップでワークスペースタブの入力欄の上にも取引文を出す。

## 3. ステップの種類(操作の語彙)

四択は使わない。すべて「操作して結果を見る」形にする。

| 種類 | 学習者がすること | 確認の仕方 | 狙い |
|---|---|---|---|
| **observe** | 読む。必要なら仕訳が自動で記帳され、結果の変化を見る | なし(次へ) | 物語の導入、用語の命名、結果の読み方 |
| **post** | 取引を自分で仕訳し、記帳する | 期待する仕訳(別解あり)と一致。外れたら誤答パターンで誤解を判定し、影響の差分を見せる | 借方・貸方の判断、科目の選択 |
| **predict** | 記帳の前に「資産・負債・純資産・収益・費用はどう動くか」を予想してから実行する | 予想と実際の差を並べて見せる(間違えても進める) | 処理の暗記ではなく影響の理解 |
| **tweak** | 金額・耐用年数・残存価額などの条件をスライダーで変え、財務諸表の変化を見る。「減価償却費が150,000円になる耐用年数にする」のような目標がある | 目標の条件を満たす | 式の意味を体で覚える。what-if |
| **classify** | 勘定科目を資産・負債・純資産・収益・費用の箱に入れる | 全部正しい。間違えた科目には「なぜその要素か」 | 要素の分類 |
| **calc** | 財務諸表を読んで数値を答える、または計算する | 値の一致。既知の誤答値に誤解を付ける | 読む力、計算 |

### 誤りの見せ方
「不正解」の一言で終わらせない。postで違う仕訳を記帳しようとしたとき:
1. 期待する仕訳を**先に見せない**。学習者の仕訳の影響(5要素の増減)と、期待される影響を並べて、ずれた要素を強調する。
2. 誤答パターンに一致したら、その誤解の説明(何を取り違えているか、正しい見方)を出す。
3. 「もう一度」で仕訳を直す。2回目以降はヒント、3回目で解答を見られる。

## 4. 単元の構成(学習フロー)

1単元 = 1つの小さな会社の物語。開始時の残高(例: 現金1,000,000 / 資本金1,000,000)から始め、ステップごとに取引を記帳して帳簿が育つ。

```
ステップ1  observe   物語の導入。この単元で何ができるようになるか(1画面)
ステップ2〜7 post / predict / tweak / classify / calcを混ぜる。説明は各ステップ短く
ステップ 最後 ふりかえり  何を学んだか、どの概念とつながるか、次の単元へ。自由に試せるサンドボックス
```

- 最初の単元(5要素と仕訳)はカフェの開業。出資 → 設備の購入 → 借入 → 売上 → 家賃 → 月末の財務諸表。
- 減価償却の単元は同じカフェの決算。コーヒーマシンを買った年に全額費用にするとどう見えるか(tweakで試す)→ 配分する → 累計額の意味 → 定額法の計算。
- 要件1章の5つの観点(何を / なぜ / 原理 / 処理 / つながり)は節ではなくステップの流れに埋め込む。導入ステップが「何を・なぜ」、操作ステップが「原理・処理」、ふりかえりが「つながり」。

## 5. 文体

- 「です・ます」で語りかける。1文は短く。教科書の定義文から始めない。
- 用語は操作の後に名前を付ける: 「左に書いた現金が増えました。この左側を **借方** と呼びます」。
- 具体例は学習者自身の会社(カフェ)で統一し、数字は暗算できる大きさにする。
- 「〜を理解しましょう」「〜に注意が必要です」のような指示的な文は避け、「〜してみましょう」「〜が見えましたか」と操作に誘う。

## 7. 検討した別案
- **解説ページ + 演習の分離(現状)**: 読む量が多く、操作が「解説の後のテスト」になる。IDE型に置き換える。
- **仕訳を選択式で組み立てる(科目をプルダウンから選ぶ)**: 入力より速いが「科目名を思い出す」訓練にならない。自由入力 + 補完(datalist)を維持する。
- **ドラッグ & ドロップ中心のUI**: 直感的だがキーボード操作と画面幅に弱い。クリックと入力で完結させ、ドラッグは仕分けボードにだけ上乗せする。
- **ゲーム化(スコア、ストリーク)**: 動機づけには効くが、まず学習ループそのものを検証する。

## 8. ビジュアル言語(2026-11-07追加)

5要素はアプリ全体で同じ色・記号・名前の3点セットで表す(`src/lib/elements.ts`)。色だけに依存しない。
具体的な色はテーマが決める(`docs/design-system.md`、ADR 0008)。下表の色は「色相の系統」で、全テーマで共通。記号も全テーマで共通。

| 要素 | 色 | 記号 | 使う場所 |
|---|---|---|---|
| 資産 | 空色(sky) | ◆ | 仕訳帳の行、財務諸表の見出し、仕分けボードの箱、影響の表示、用語ポップオーバー、用語集 |
| 負債 | 赤(rose) | ▲ | 同上 |
| 純資産 | 紫(violet) | ● | 同上 |
| 収益 | 緑(emerald) | ＋ | 同上 |
| 費用 | 橙(amber) | － | 同上 |

- 仕訳帳の行は、科目が決まった瞬間にその要素の色に変わり、バッジと一文の説明が出る。間違った科目名は赤字で知らせる。
- 仕訳帳の科目候補は5要素ごとにまとめ、要素色の見出し(記号 + 要素名)の下に科目名と一文の説明を並べる。ブラウザの`<datalist>`ではなく自前のコンボボックス(`src/components/account-combobox.tsx`)で描く。
- 財務諸表は科目名にホバー / タップで意味と要素が出る(用語ポップオーバーを流用)。動いた行は一瞬光り、▲▼ で差分を示す。
- 「会社のかたち」: 貸借対照表の上に、左に資産、右に負債 + 純資産の帯を同じ幅で並べる。記帳のたびに幅がなめらかに変わり、「資産は負債と純資産でまかなわれる」構造が目で分かる。
- 「帳簿をさかのぼる」: 結果ペインのスライダーで、記帳を1件ずつ巻き戻して財務諸表を見られる(プログラミングの履歴やundoに相当)。
- フォントはNoto Sans JP。動きは`prefers-reduced-motion`を尊重する。

## 9. オンボーディング(2026-11-07追加)

- 初めて単元を開いた学習者(回答も進捗もまだ無い学習者)には、ガイドの上に「2分のチュートリアル」への案内を出す(「今はしない」で消え、「使い方」の案内の設定も外れる。付け直せば、未着手の単元でまた出る)。
- チュートリアルは専用の短い単元(`tutorial/first-entry`、一覧には出ない)の上で動く操作ツアー。対象を明るく残して周りを暗くし、「次へ → を押す」「借方に現金を入れる」「記帳する」などユーザーの操作が済むまで待つ。「次へ →」や「記帳する」を押す段は、押せば次の段へ進む。金額を入れる段は打鍵の途中で進めないよう、入れ終えたら「できました。このカードの「次へ」で進みます」と示し、カードの「次へ」で進む。説明だけの段は「次へ」で進む。操作を待っている間、カードの最後の操作からTabを押すと案内先へ移る。
- いつでも「スキップ」で終了できる。途中でスキップすると初回案内の設定も外れる(付け直せば戻る)。ヘッダーの「使い方」から、各機能の説明の確認、チュートリアルのやり直し、初回案内の表示 / 非表示の切り替えができる。
- 状態(未実施 / スキップ / 完了、案内の表示設定)はブラウザに持つ(本登録後はアカウントに持たせる)。
- 「使い方」の構成(いまの画面 / 分類ごとの折りたたみ)、機能の隣の「?」、初めて出る課題の種類の案内は`docs/help-design.md`。

### 10. アイデアの保留箱(優先順)
1. **取引の流れのアニメーション**: 記帳した瞬間に、仕訳の各行が財務諸表の該当行へ移動する(矢印または数字の飛び)。
2. **T勘定タブ**: ワークスペースに総勘定元帳を追加し、科目ごとの増減を左右で見る。
3. **期を締める**: 収益・費用を繰越利益剰余金へ振り替え、複数年のシナリオ(2年目の決算、売却)を自然に扱う。
4. **図解ブロック**: 説明文に`diagram`ブロックを置き、取引 → 仕訳 → 財務諸表の流れや、費用配分の図をSVGで描く。
5. **サンドボックス単元**: 自由な会社をゼロから作り、好きな取引を記帳して財務諸表を育てる。
6. **概念マップ**: 学習済み / 誤解の多い概念を重ねて表示。
7. **立ち止まり**: 同じ思い込みが2回続いたら短い診断ステップを挟む。
