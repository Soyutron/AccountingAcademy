# 開発方針とロードマップ(v1)

更新日: 2026-11-07
状態: 採用。ビジョンとギャップは `docs/vision.md`。マイルストーンの順序は固定し、各マイルストーンの中身は着手時に見直す。

## 1. 開発方針

1. **学習体験の検証を最優先する。** 各マイルストーンは「テスターが触れる状態」で終える。作って終わりにしない。
2. **縦に薄く、横に広げる。** 新しい課題の種類や機能は 1 単元で試し、効果を確かめてから量産する。
3. **content as code を守る。** コンテンツはビルドで検査し、E2E が全単元を自動で解く。単元を増やしても検証コストを増やさない。
4. **会計 IDE の独自性に投資する。** 既存教材の再現(動画、四択、暗記カード)には投資しない。迷ったら「操作して結果を見る」形にする。
5. **個人開発として持続させる。** 保守対象を増やさない。ADR で決めたことを守り、変えるときは ADR を書く。AI エージェントが働きやすい構造(docs、Skills、MCP、テスト)を保つ。
6. **測って直す。** 回答ログから誤解の分布と初回正答率を見て、解説と誤答パターンを改善する。感想だけで判断しない。

## 2. マイルストーン

規模感は個人開発 + AI エージェントの前提での目安。日付は置かず、順序と完了条件で管理する。

### M1 学習ループを信じられる状態にする(目安 3〜4 週)
目的: 3 級の基礎テーマを会計 IDE で学べるようにし、教育方針を検証する。
進捗(2026-11-07): 実装項目はすべて完了。図解ブロック 6 種、取引の流れのアニメーション、T 勘定タブ、オンボーディング、CI、匿名ユーザーの定期削除、コンテンツは 5 テーマ 13 単元(簿記の仕組み、減価償却、商品売買、現金・預金、債権・債務)。残りはユーザー自身による検証(`docs/testing-guide.md`)と、その結果に基づく調整。
- コンテンツ: 商品売買、現金・預金、債権・債務のテーマを IDE 形式で執筆(合計 10 単元前後)。既存 3 単元の文体と密度を基準にする。
- IDE: 図解ブロック(`docs/visual-guidelines.md` 5 章の 6 種)、取引の流れのアニメーション(記帳した仕訳の行が財務諸表の該当行へ飛ぶ。`motion` を導入)、T 勘定タブ、最初の 2 分のオンボーディング(IDE の使い方を 1 ステップで)。
- 運用: GitHub Actions で lint・型・テスト・コンテンツ検査・E2E、匿名ユーザーの定期削除。ホスティングは未決のまま(ローカルで検証)。
- 検証: 当面はユーザー自身がテスターを務める。要件 6.2 の指標(完走率、predict の初回正答率、理解度チェック、気づき)をローカルの Supabase から集計する。
- 完了条件: 検証結果が出て、教育方針を続けるか見直すか判断できる。

### M2 会計ならではの課題を増やす(目安 3〜4 週)
目的: ビジョン 4 章の学び方を課題の種類として実装し、各 1 単元で試す。
- 課題の種類: バグ探し(debug)、同じ取引・別の方法(compare)、分岐(branch)、逆算(reverse)。
- 決算パイプライン: 仕訳帳 → 総勘定元帳 → 試算表 → 決算整理 → 精算表 → 財務諸表を段階ごとに見られる「決算」タブ。
- エンジン: 期を締める(収益・費用を繰越利益剰余金へ振り替え)、評価勘定を含む開始残高。複数年のシナリオを扱えるようにする。
- 完了条件: 4 種の課題がそれぞれ 1 単元で動き、テスターの反応が記録されている。

### M3 3 級を通しで学べる(目安 6〜8 週)
目的: 3 級合格パスを 1 本通しで学べるようにし、合格に足る総合力を付けられるようにする。
- コンテンツ: 3 級の残り全テーマ(固定資産の売却、資本と税金、決算整理、精算表、伝票・補助簿など)で合計 50 単元前後。
- 総合課題: 1 か月の会社を通して記帳し決算する「プロジェクト」単元。
- 模擬試験: CBT と同じ時間・構成の模試(パス固有)。修了証。
- 概念マップ: 前提・関連・対比を可視化し、学習済みを重ねる。
- 完了条件: テスターが 3 級パスを完走し、模試で合格点を取れる。

### M4 定着と伴走(目安 4〜6 週)
目的: 学習者ごとの状態に応じて支援し、長く使ってもらう。
- 本登録(メール / Google)、デバイス間同期、学習ダッシュボード。
- 復習: 間隔反復の復習キュー(誤解の出た課題と predict を優先)。短時間で済む復習モード。
- 立ち止まり: 同じ誤解が続いたら診断ステップを挟む。習熟度の推定(まずは単純な正答率)。
- (AI 解説は対象外。将来サブスクリプションを導入する際に改めて検討する)
- 集計: 誤解 ID ごとの発生率、課題ごとの初回正答率の集計画面(自分用)。
- 完了条件: 復習と介入が動き、再発率の指標が取れる。

### M5 2 級と「かたちで読む」(目安 10〜12 週)
目的: 2 級範囲に広げつつ、合格後も使える「読む力」の体験を作る。
- コンテンツ: 2 級商業簿記・工業簿記。テーマ軸の深さ 3 を埋める。
- かたちで読む: 比例縮尺の貸借対照表・損益計算書。実在企業の決算(EDINET)を読み込み、形を比べ、「どの会社か」を当てる課題。
- サンドボックス: 自分の会社を開業し、1 年を運営して決算する。作った会社を共有できる。
- 完了条件: 2 級パスが通しで学べ、実データの課題が動く。

### M6 プラットフォームへ(以降)
- 1 級・公認会計士・税理士の理論パス、実務コース(確定申告、経理の月次)。
- 企業研修(チーム管理、進捗の見える化)、学校での利用。
- コミュニティ(作った会社・分析の共有)。
- 料金プラン(無料枠を維持)。

### 継続的に行うこと
- デザインの洗練: デザインシステムの整備、図解とイラストの追加、ダークモード、アクセシビリティ。
- 性能と品質: Lighthouse、E2E の拡充、Skills / MCP の更新。
- コンテンツの改善: 回答ログに基づく解説と誤答パターンの見直し。

## 3. 直近 2 週間の着手順

1. 図解ブロック(`elements` / `flow` / `timeline` / `taccount` / `proportion` / `compare`)の実装と、既存 3 単元への図解の追加。
2. 取引の流れのアニメーションと T 勘定タブ。
3. 商品売買テーマの執筆(三分法、掛け取引、返品)。既存単元を基準に 3〜4 単元。
4. CI(GitHub Actions)とオンボーディングの 1 ステップ。
