# 図解・イラスト・アニメーションの方針(v1)

更新日: 2026-11-07
状態: 採用(ADR 0004)。会計 IDE の視覚表現をどの場面で、どの手法で作り、どう運用するかを定める。配色と記号は `docs/ide-design.md` 8 章。

## 1. 原則

1. **視覚表現は説明に従属する。** 読み飛ばせる装飾は置かない。すべての図は「その図が無いと分かりにくいこと」を 1 つ持つ。
2. **会計の構造は「図解」で、物語の場面は「イラスト」で。** この 2 つを混ぜない。図解は正確さと一貫性、イラストは親しみやすさが役目。
3. **動くものが本体。** 会計 IDE では、学習者の操作に応じて財務諸表や帯が動くこと自体が最良の視覚表現。静止画の図解は、その動きの「説明書」として添える。
4. **1 つの視覚言語。** 5 要素の色と記号(ide-design.md 8 章)、線の太さ、角丸、余白を図解・イラスト・UI で共通にする。素材を複数のソースから混ぜない。
5. **色に頼らない。** 記号・ラベル・形で区別し、alt テキストを必ず書く。装飾は `aria-hidden`。
6. **ライセンスは台帳で管理する。** 外部素材は出所・ライセンス・使用箇所を記録し、点数制限のある素材は使わない。

## 2. 場面ごとの視覚表現

| 場面 | 何を見せたいか | 手法 | 例 |
|---|---|---|---|
| 財務諸表の動き(結果ペイン) | 記帳で何がどれだけ動いたか | データ駆動の UI(実装済み)+ 遷移アニメーション | 動いた行の強調、▲▼、「会社のかたち」の帯 |
| 取引の流れ | 仕訳の行が財務諸表のどこへ行くか | アニメーション(M1): 数字が該当行へ飛ぶ | 「現金 80,000」が貸借対照表の現金へ |
| 会計の構造(5 要素、貸借の左右、評価勘定) | 位置関係と包含関係 | 図解ブロック `elements` | 5 つの箱に科目を置いた図 |
| 手続きの流れ(決算パイプライン、三分法の流れ) | 順序と段階 | 図解ブロック `flow` | 仕訳帳 → 総勘定元帳 → 試算表 → 財務諸表 |
| 期間と配分(減価償却、経過勘定) | 時間軸上の分け方 | 図解ブロック `timeline` | 1,200,000 円を 6 年に分ける |
| 科目の増減(T 勘定) | 左右の積み上がり | 図解ブロック `taccount`(M1 で IDE のタブにも) | 現金の T 勘定 |
| 方法の比較(直接法 / 間接法、定額法 / 定率法) | 同じ取引で何が違うか | 図解ブロック `compare`(2 つの図を左右に) | 間接法では建物の金額が残る |
| 会社の形(比例縮尺) | 全体像と割合 | 図解ブロック `proportion`(M6 で実データにも) | 資産 vs 負債 + 純資産 |
| 物語の場面(カフェ、コーヒーマシン、軽バン) | 親しみ、場面転換の合図 | スポットイラスト(小さく、ステップ見出しの横) | 開業日のカフェ |
| 概念のたとえ(費用配分 = ケーキを切り分ける) | 直感的な理解の足がかり | 図解ブロックで描けるものは図解で。描けないものはスポットイラスト | 6 等分のケーキ |
| UI の記号 | 操作の手がかり | アイコン(Lucide のみ) | ✓、!、→ |
| 達成・区切り | 感情の起伏 | 控えめなアニメーション(入場・強調)。正解した瞬間だけ短い紙吹雪を 1 回(1.5 秒以内、画面を覆わない、セッション中の初回だけ、`prefers-reduced-motion` では出さない)。音は出さない | 「できました」のフェードイン、紙吹雪、「次へ →」の 1 回のパルス |

## 3. 手法・ツールの比較

### 3.1 図解(構造・流れ・期間)

| 手法 | 長所 | 短所 | 判定 |
|---|---|---|---|
| **コードで描く(React + SVG の図解コンポーネント、コンテンツからは YAML の `figure` ブロックで指定)** | 5 要素の配色・記号と自動で一致。ダークモードやスマートフォン幅に追従。数値を渡せば比例縮尺も描ける。アニメーションに繋げられる。ライセンスの問題がない。AI エージェントが YAML を書くだけで量産できる | 図の種類ごとにコンポーネントを作る初期コスト。自由な絵は描けない | **採用** |
| Excalidraw(手描き風の作図ツール、MIT) | 自由に描ける。手描き風は親しみやすい | 配色・線の統一が人手頼み。数値と連動しない。SVG を手で貼る運用になる | 図解ブロックで表せない図が出たときの補助。一次手段にしない |
| Mermaid / D2(テキストから作図) | テキストで管理できる | 見た目の制御が弱く、会計の図(左右の箱、比例)に向かない | 不採用 |
| 画像(PNG)で図を置く | 作るのは早い | 更新しにくく、文字が拡大でぼやけ、配色がずれる | 不採用 |

### 3.2 イラスト(物語の場面・たとえ)

| 素材 | ライセンス(2026-11-07 時点、公式ページ確認) | 統一感・拡張性 | 判定 |
|---|---|---|---|
| **いらすとや** | 商用可。無料は「1 つの制作物につき 20 点まで(重複は 1 点)」。「無料で閲覧できるオープンなサイト」でコンテンツが増え続ける場合は 1 記事 20 点まで。21 点以上は 1 点 1,100 円(税込)目安。加工可だが「いらすとやと分からなくする加工」は不可。クレジット不要 | 誰もが知るスタイルで、サービスの印象が「いらすとや」になり、独自性と洗練から遠ざかる。無料公開の間は単元ごとに 20 点まで使えるが、将来サブスクリプションにすると「オープンなサイト」の条件を外れ、全体で 20 点の上限に戻る可能性が高い(規約に明文は無い) | **主要素材としては不採用**。ビジョン(独自の学び方)と料金方針(将来の有料化)の両方と相性が悪い |
| **unDraw** | 商用可、帰属不要、点数制限なし。禁止は素材集としての再配布と AI 学習への利用 | SVG で配布され、サイト上で 1 色を指定して再着色できる(本サービスの空色に統一可)。フラットで控えめ。人物は西洋的で、日本の場面(軽バン、商工会議所)は無い | **スポットイラストの第一候補** |
| Loose Drawing | 商用/非商用・個人/法人とも無料。点数制限の記載なし。クレジット不要。加工可。再配布・販売は不可。無料は PNG(サイト上で色変更可)、SVG は有料 | 日本の作者による線画で、日本の場面に合う。人物中心。PNG 運用になるので解像度と再着色に制約 | 第二候補(日本的な場面が要るとき) |
| Open Peeps / Open Doodles | CC0 | 人物の手描き風。物や場面の表現は少ない | 人物だけ必要なら候補 |
| Storyset(Freepik) | 無料は帰属表記が必要 | 点数も表現も豊富だが帰属表記が UI に残る | 不採用 |
| AI 画像生成 | サービスごとに異なる。生成物の権利の扱いが不安定 | 枚数は無限だが、スタイルと細部(指、文字、会計の記号)の一貫性を保つ運用コストが高い。学習用の正確さが要る図には向かない | 不採用(図解・学習用)。マーケティング用の 1 枚などに限って将来検討 |
| 自作・委託(独自キャラクターとスタイルガイド) | 権利が明確 | 費用と時間。サービス名とブランドが決まってから | M4 以降、ブランド決定後に検討。それまでは図解とスポットイラストで足りる構成にする |

### 3.3 アニメーション

| 手法 | 用途 | 判定 |
|---|---|---|
| **CSS transition / keyframes、tw-animate-css** | 入場・強調・幅の変化。`prefers-reduced-motion` で止める | **採用(実装済み)** |
| **`motion`(旧 framer-motion、MIT)** | レイアウトの移動(数字が財務諸表の行へ飛ぶ)、共有要素の遷移 | M1 の「取引の流れ」で導入 |
| React の View Transitions | ページ間の連続性 | 必要になってから |
| Lottie / Rive | 作り込んだキャラクターアニメーション | 不採用(制作ツールと運用が増える) |

ルール: 動かすのは状態が変わったときだけ。150〜500 ms。ループする装飾は置かない。動きには必ず静的な表現(▲▼、色、テキスト)が伴う。

## 4. 決定

1. **図解はコードで描く。** 図解ブロック(5 章)を作り、コンテンツからは YAML で指定する。種類は必要になった順に足す。
2. **イラストは当面最小限。** 物語の場面転換に使う小さなスポットイラストだけとし、素材は unDraw に絞って本サービスの色で再着色する。いらすとやは主要素材に使わない。
3. **AI 生成画像は学習コンテンツに使わない。**
4. **アニメーションは CSS を基本に、M1 で `motion` を導入する。** Lottie / Rive は使わない。
5. **独自のイラストスタイル(キャラクター含む)は、サービス名とブランドが決まってから検討する(M4 以降)。** それまでの構成は、図解とスポットイラストだけで成立させる。

## 5. 図解ブロックの仕様(M1 で実装)

説明文に ```figure ブロック(YAML)を置く。`type` ごとに zod で検査し、`src/components/figures/` の SVG コンポーネントが描く。すべて `ELEMENT_STYLE` の色と記号を使い、`alt` を必須にする。

```yaml
# 5 要素の箱に科目を置く。left に資産、right に負債・純資産、下に収益・費用
type: elements
alt: 現金と備品は資産の箱に、借入金は負債の箱に入る
items:
  - { account: cash, highlight: true }
  - { account: equipment }
  - { account: loans_payable }
```

```yaml
# 流れ図。ノードは左から右(スマートフォンでは上から下)
type: flow
alt: 取引が起きると仕訳帳に書き、集計して財務諸表になる
nodes: [取引, 仕訳帳, 総勘定元帳, 試算表, 財務諸表]
highlight: 1
```

```yaml
# 期間と配分。合計を n 期に分け、各期の額を示す
type: timeline
alt: 1,200,000 円を 6 年に分けると、毎年 200,000 円
total: 1200000
periods: 6
unit: 年
```

```yaml
# T 勘定
type: taccount
alt: 現金の T 勘定。左に増加、右に減少
account: cash
debit: [{ label: 出資, amount: 1000000 }, { label: 売上, amount: 80000 }]
credit: [{ label: 備品の購入, amount: 600000 }]
```

```yaml
# 比例縮尺の貸借対照表(と損益計算書)
type: proportion
alt: 資産 1,330,000 のうち、負債が 300,000、純資産が 1,030,000
assets: [{ account: cash, amount: 730000 }, { account: equipment, amount: 600000 }]
liabilities: [{ account: loans_payable, amount: 300000 }]
equity: [{ account: capital_stock, amount: 1000000 }, { label: 当期純利益, amount: 30000 }]
```

```yaml
# 2 つの図を左右に並べる
type: compare
alt: 直接法は建物を直接減らし、間接法は累計額で減らす
left: { title: 直接法, figure: { type: elements, items: [...] } }
right: { title: 間接法, figure: { type: elements, items: [...] } }
```

追加の候補(必要になったら): `journal-to-statements`(仕訳の各行が財務諸表のどこへ行くかを矢印で示す静止版)、`cycle`(会計期間の循環)。

## 6. 運用

- 置き場所: 図解はコード(`src/components/figures/`)とコンテンツ(```figure)。外部イラストは `public/illustrations/<source>/<name>.svg`。
- 台帳: `docs/assets-ledger.md` に、ファイル名 / 出所 URL / ライセンス / 取得日 / 使用箇所を 1 行ずつ記録する。外部素材を足すときは必ず同時に書く。
- 再着色: unDraw の SVG はダウンロード時に既定テーマの差し色(`--brand-accent`。docs/design-system.md)を指定する。手で色を変えない。テーマごとの再着色は将来の課題(design-system.md 7 章)。
- アクセシビリティ: 図解ブロックは `alt` 必須(ビルドで検査)。図の中の文字は 12px 以上。装飾のイラストは `aria-hidden`。
- ダークモード: 図解は CSS 変数で配色を切り替える。イラストは背景が透過のものだけ使う。
- 命名と粒度: 1 図 1 メッセージ。1 ステップに図は 1 つまで。説明文の 2〜4 文を超える図解は置かない。
- 見直し: 回答ログで初回正答率が低いステップに図解を追加する(roadmap 方針 6)。
