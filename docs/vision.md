# プロダクトビジョン(v2)

更新日: 2026-11-08
状態: 採用(ユーザー決定 2026-11-08)。ロードマップは `docs/roadmap.md`、公開とライセンスの方針は ADR 0007。v1 からの差分は末尾。

## 1. 北極星

**日本の会計教育に、オープンソースの文化を。**

誰もが経済的な制約なく質の高い会計教育にアクセスでき、学んだ知識を共有し、互いに教え合い、よりよい教材を共同で作り上げていく。
日本の会計知識が集まり、共有され、検証され、継続的に進化していくオープンな教育基盤を目指す。

学習体験の中核は v1 から変えない。**会計を、読むのではなく、書いて動かして理解する。** 会計 IDE で仕訳を記帳し、財務諸表が動くのを見て、原理・構造・つながりを体で理解する。
v2 で変わるのは「誰が作り、誰のものか」。教材・解説・演習を特定の個人や企業の資産ではなく、コミュニティが育てる共有財産にする。
IT 業界が育ててきた知識共有と共同開発の文化(Pull Request、Issue、Q&A、記事、コンテスト)を、模倣ではなく会計教育に合う形に翻訳して取り入れる。

## 2. 基本原則

| 原則 | 意味 | このプロジェクトでの具体 |
|---|---|---|
| 教育へのアクセスを開く | 全機能・全コンテンツを無料で使える。ログインを強制しない | 既に無料・ゲスト優先。料金プランと課金のための機能分割をロードマップから外す。収益化を否定はしないが目標にしない |
| 知識を共有財産にする | 教材は誰でも複製・改変・再配布できる | コンテンツにオープンライセンスを付ける(ADR 0007)。`content/` が正本で、履歴は git に残る |
| 学習者を貢献者にする | 学ぶ → 合図を送る → 聞く・答える → 直す → 書く → 守る、の段差を小さくする | 単元ごとの「誤りを報告」「この単元を改善」導線、プレビューで動かすレビュー(6 章) |
| 会計の本質を学ぶ | 試験合格は途中の成果。原理・構造・つながりを学ぶ | 概念中心のテーマ軸(ADR 0002)。変更なし |
| オープンソースを基本とする | コードに加え、教材のライセンス、貢献ルール、意思決定を公開する | LICENSE / CONTRIBUTING / CODE_OF_CONDUCT / ADR。レビュー基準を文書にする |
| AI を活用する | 開発・執筆の下書き・検証は AI に任せ、人は専門知識の共有と判断に集中する | 品質改善ループ(`docs/quality-loop.md`)。AI は下書きと検査を担い、公開の可否は人が決める |
| 持続可能性を重視する | 短期の収益より、長く価値を生む仕組みと小さな固定費 | VPS 1 台(ADR 0006)、保守対象を増やさない。運営費の賄い方(寄付・スポンサー)は利用者が付いてから検討する |

## 3. 学習体験の 5 つの柱(v1 から維持)

| 柱 | 意味 | いまの実装 |
|---|---|---|
| 動かして学ぶ | 仕訳 → 記帳 → 財務諸表の即時反映。読む時間より手を動かす時間が長い | 会計 IDE(3 ペイン、6 種のステップ) |
| 原理から学ぶ | なぜ存在するか、5 要素の増減、財務諸表への影響、概念のつながり | ステップの流れに埋め込む設計、用語ポップオーバー |
| 誤解に気づく | 誤りを「不正解」で終わらせず、影響の差分で見せ、思い込みを名指しして解きほぐす | 誤答パターンと誤解 ID、影響の比較 |
| 体系で学ぶ | 概念中心のテーマ軸に、3 級 / 2 級 / 1 級 / 会計士 / 実務の目的別パスを重ねる | テーマ・概念・パスの構造(ADR 0002) |
| 使い続けられる | 合格後も用語集・サンドボックス・実データの分析に戻ってこられる | 用語集のみ |

## 4. 会計ならではの学び方(差別化の中核。v1 から維持)

プログラミング IDE の道具を、ひとつずつ会計に翻訳する。既存の会計教材には無く、会計 IDE だからできる学び方。
コミュニティ機能より先に、ここを磨く。人が集まり、残る理由はここにしかない。

| 学び方 | プログラミングの比喩 | 会計 IDE での体験 | 状態 |
|---|---|---|---|
| 記帳して実行 | コードを書いて実行 | 仕訳を記帳すると財務諸表が動く | 実装済み |
| 予想してから実行 | テスト駆動 | 5 要素の動きを予想 → 記帳 → 予想と実際を比較 | 実装済み |
| 差分レビュー | git diff | 記帳前後の財務諸表の差分。あなたの仕訳 vs 期待される影響 | 実装済み |
| 履歴をさかのぼる | git log / undo | 帳簿を 1 件ずつ巻き戻して、会社の姿の変化を追う | 実装済み |
| 条件を変える | パラメータ・設定 | 耐用年数や金額をスライダーで動かし、結果をその場で見る | 実装済み |
| バグ探し | デバッガ | 帳簿に紛れた誤った仕訳を、財務諸表の違和感から見つけて直す | 未 |
| 同じ取引、別の方法 | 同じ出力の別実装を比べる | 直接法と間接法、定額法と定率法、三分法と分記法を同じ取引で並べる | 未 |
| 分岐 | ブランチ | 「借りる」か「出資を受ける」かで、財務諸表の未来を分岐させて比べる | 未 |
| 決算をコンパイルする | ビルドパイプライン | 仕訳帳 → 元帳 → 試算表 → 決算整理 → 精算表 → 財務諸表を段階ごとに見る | 未 |
| 逆算 | リバースエンジニアリング | 財務諸表の変化から、どんな取引があったかを推理して仕訳を書く | 未 |
| かたちで読む | 可視化 | 比例縮尺の貸借対照表・損益計算書で会社の形を読む | 一部 |
| 実データで遊ぶ | OSS のコードを読む | 実在企業の決算(EDINET の XBRL)を読み込み、形を比べ、何が起きたかを考える | 未 |
| 自分の会社を育てる | 個人プロジェクト | サンドボックスで会社を開業し、1 年を運営して決算する。作った会社を共有する | 一部 |

## 5. IT の文化を会計教育に翻訳する

サービスをそのまま真似るのではなく、設計思想(何がその文化を機能させているか)を取り出して、会計教育の形に置き直す。

| 文化・サービス | 機能させている設計思想 | 会計教育での形 | 既にあるもの | 段階 |
|---|---|---|---|---|
| Codecademy | learn by doing。小さなチェックポイントを順に通し、結果がすぐ見える | 会計 IDE(3〜4 章) | 実装済み | 1 |
| GitHub Pull Request | 変更が差分で見え、自動検査とレビューを通ってから取り込まれる。誰の変更かが残る | 教材の修正提案。スキーマ検査・貸借一致・E2E に加え、プレビュー環境で実際に解いてレビューする。誰の変更かは git 履歴と GitHub に残る | content as code、Velite の横断検査、E2E、issue-agent | 1〜2 |
| GitHub Issues | 不具合と提案を公開で一覧し、状態をラベルで持つ | 教材の誤り・改善要望。単元のステップから 1 クリックで、文脈つきで起票 | Issue 駆動の開発、Monkey の起票、トリアージ | 1 |
| Stack Overflow | 質問が検索できる公共の知識になり、良い回答が上に来る。重複は統合される | 単元・ステップに紐づく質問と回答。回答から教材の修正(Issue / PR)へつなぐ | 無し | 3 |
| Qiita / Zenn | 個人の声で気軽に書ける。GitHub 連携で Markdown のまま公開できる | 解説記事・学習記録・実務の知見。良い記事は査読を経て単元や概念の解説へ昇格する | 無し | 4 |
| AtCoder | 自動採点の問題で競う。問題は作問者コミュニティが作り、過去問が教材として残る | 会計コンテスト(逆算、バグ探し、総合問題)。ユーザー作問が演習の供給源になる | 採点エンジン(純粋関数)、課題の種類 | 5 |
| OSS コミュニティ | 保守者、行動規範、透明な意思決定、貢献の可視化 | テーマごとの保守者(CODEOWNERS)、行動規範、ADR、GitHub の contributors | ADR、docs | 2〜 |

優先順位は「既にある構造を開く(PR / Issue)→ 学習の場から自然に出る行為(質問)→ 発信(記事)→ 競う(コンテスト)」の順。
理由は 2 つ。構造が既にあるものはコストが小さいこと、質問は学習中に必ず生まれるが記事やコンテストは利用者の母数が要ること。

教材(査読される知識、PR で変わる)と記事(個人の声、軽い審査)と質問(文脈つきの対話)は別の器にする。全部を 1 つの「投稿」にすると、教材の正確さと発信の気軽さの両方を失う。

## 6. 学習者が貢献者になる階段

| 段 | 行為 | 要るもの | 所要 |
|---|---|---|---|
| 0 | 学ぶ | 会計 IDE | |
| 1 | 合図を送る: 「分かりにくい」ボタン、誤りを報告 | 単元・ステップからの起票導線(Issue テンプレートに文脈を自動で入れる) | 10 秒 |
| 2 | 聞く・答える | 単元に紐づく Q&A | 数分 |
| 3 | 直す: 文言や例の修正 | GitHub の Web 編集、PR のプレビュー環境 | 10 分 |
| 4 | 書く: 記事、新しい演習・単元 | 執筆ガイド(`docs/content-model.md`)、テンプレート、AI の下書き・検査 | 数時間 |
| 5 | 守る: テーマの保守者としてレビューする | レビュー基準、CODEOWNERS | 継続 |

階段を自然に上らせる仕掛け:
- **学習データを貢献の種にする。** 誤答パターンに無い誤答が多い課題、初回正答率が低いステップを集計し、匿名の「つまずきマップ」として公開し、Issue に変える(Issue #23 はこの型の第 1 号)。利用者が増えるほど「直すべき場所」が明確になり、貢献の入口が自動で増える。
- **文脈を失わない。** 質問・報告・PR はすべて「どの単元のどのステップか」を持つ。回答者も学習者と同じ画面を見て答えられる。
- **名前が残る。** 取り込まれた変更は git 履歴と GitHub の contributors に著者として残る(単元ページへの表示は作らない)。記事と回答にも署名が付く。
- **動かしてレビューする。** コンテンツの PR はプレビュー環境で実際に解ける。会計の専門家は開発者でなくてもレビューできる。
- **空き部屋を作らない。** Q&A・記事・コンテストは、利用者数と報告数の条件を満たしてから開く(roadmap 1 章 7 項)。誰もいない掲示板は信頼を下げる。
- **git の壁を測る。** 段 3 で止まる人が多いと分かってから Web 編集 UI に投資する。先回りして作らない。

## 7. 品質・正確性・ライセンス・運営

### 7.1 品質の 4 層
| 層 | 内容 | 状態 |
|---|---|---|
| 機械 | Velite のスキーマと横断検査(用語の未説明、前提の循環、貸借一致、誤答パターンの整合)、E2E が全単元を自動で解く、Monkey のコンテンツ監査人格 | あり |
| レビュー | 2 段階。文言・例の修正は保守者 1 名。会計処理・計算・誤解の説明の変更は、そのテーマの保守者(専門性のある人)の承認を要する。深さ 3〜4 の単元は出典(会計基準、企業会計原則、法令)を必須にする | 基準の文書化が未 |
| 事後 | 回答ログで課題ごとの初回正答率と誤解の分布を追い、変更後に悪化したら差し戻す | 集計 SQL のみ |
| 鮮度 | 会計基準・税法・日商簿記の出題区分は改定される。単元に確認日を持ち、古いものを一覧できるようにする。試験範囲の改定はパスだけで吸収する(ADR 0002) | 未 |

### 7.2 ライセンスと権利(ADR 0007)
- コードとコンテンツは別のライセンスにする。コンテンツは改変物も開いたままにする(継承)。
- 貢献は DCO(署名付きコミット)で「自分に権利があり、プロジェクトのライセンスで提供する」ことを明示する。CLA は置かない。
- 日商簿記の過去問・公式問題は転載しない。PR テンプレートの確認項目に入れる。教科書からの転記も不可。
- 外部イラストは unDraw のみ(ADR 0004)。AI 生成画像は学習コンテンツに使わない。
- サービス名とロゴは商標として扱い、ライセンスの対象外にする(フォークは自由、名前は守る)。

### 7.3 運営
- 意思決定は当面は開発者 1 人(BDFL)。テーマの保守者が増えたら保守者会議へ、法人格は必要が出てから。決めたことは ADR に残す(既存の運用)。
- 行動規範は Contributor Covenant(日本語訳)を採用する。
- 学習者の回答データは集計値だけを公開する。個票は出さない。RLS で本人以外は読めない(現状)。
- 運営費は VPS と AI の利用料。利用者が付いた段階で GitHub Sponsors 等を開き、収支を公開する。

## 8. 対象ユーザーの広がり

| 段階 | 学ぶ人 | 貢献する人 |
|---|---|---|
| いま | 日商簿記 3 級・2 級の独学者。動画やテキストで挫折した人 | 開発者 1 人 + AI |
| 次 | 合格後の実務者、経理配属の新人、副業・フリーランス | 学習者(報告・質問)、実務者(回答・記事) |
| 将来 | 1 級・公認会計士・税理士の受験者 | 会計士・税理士・教員(テーマの保守者、深さ 3〜4 の執筆) |
| 将来 | 学校・企業(授業や研修で使う。自前ホストもできる) | 教員(授業用パスの作成)。専用機能(受講管理)は作らず、オープンな構造で応える |

## 10. 成功の定義(段階ごと)

| 段階 | 指標 |
|---|---|
| 1 学習体験の確立 | predict の初回正答率の推移、同じ誤解の再発率、単元の完走率 |
| 2 利用者の獲得 | 週あたりの再訪者数、パスの完走率、3 級合格の報告 |
| 3 知識共有の促進 | 学習者からの報告・質問の数、回答までの時間、回答から生まれた教材修正の数 |
| 4 コミュニティによる共同開発 | 外部からの PR の統合数、保守者の人数、開発者 1 人が書いた単元の割合(下がるほどよい) |
| 5 エコシステムの発展 | 自前ホストの事例、コンテストの参加者とユーザー作問の数、1 級・会計士パスの単元数 |

## v1(2026-11-07)からの差分
- 北極星を「日本語圏で最も分かる会計学習プラットフォーム」から「日本の会計教育にオープンソースの文化を」に変更。学習体験の中核(3〜4 章)は維持。
- 基本原則(2 章)、文化の翻訳(5 章)、貢献者への階段(6 章)、品質・権利・運営(7 章)を新設。
- 対象ユーザーに「貢献する人」の列を追加。B2B(企業研修)は専用機能ではなく、オープンな構造と自前ホストで応える形に変更。
- ギャップ表から「事業(料金プラン)」を削除し、「公開と権利」「貢献の導線」「知識共有」「共同制作」を追加。
- 成功の定義を 5 段階ごとに再編。
