# プロダクトビジョンと現状とのギャップ(v1)

更新日: 2026-11-07
状態: 採用(ユーザー方針 2026-11-07)。ロードマップは `docs/roadmap.md`。

## 1. 北極星

**会計を、読むのではなく、書いて動かして理解する。**

会計のための IDE と学習体験を一体にした、日本語圏で最も「分かる」会計学習プラットフォームを目指す。
学習者は仕訳を記帳し、財務諸表が動くのを見て、原理・構造・つながりを体で理解する。試験合格はその途中の成果であり、合格後も実務や経営判断のために戻ってくる場所になる。

## 2. 学習体験の 5 つの柱

| 柱 | 意味 | いまの実装 |
|---|---|---|
| 動かして学ぶ | 仕訳 → 記帳 → 財務諸表の即時反映。読む時間より手を動かす時間が長い | 会計 IDE(3 ペイン、6 種のステップ) |
| 原理から学ぶ | なぜ存在するか、5 要素の増減、財務諸表への影響、概念のつながり | ステップの流れに埋め込む設計、用語ポップオーバー |
| 誤解に気づく | 誤りを「不正解」で終わらせず、影響の差分で見せ、思い込みを名指しして解きほぐす | 誤答パターンと誤解 ID、影響の比較 |
| 体系で学ぶ | 概念中心のテーマ軸に、3 級 / 2 級 / 1 級 / 会計士 / 実務の目的別パスを重ねる | テーマ・概念・パスの構造(ADR 0002) |
| 使い続けられる | 合格後も用語集・サンドボックス・実データの分析に戻ってこられる | 用語集のみ |

## 3. Codecademy から学ぶこと、真似しないこと

参考にする点:
- 学習画面の 3 ペイン構造と、小さなチェックポイントを順に通す進め方(実装済み)。
- パスとカリキュラムの一貫性。「何を学べば何ができるようになるか」が常に見える。
- 詰まったときの段階的な支援: ヒント → 解答 → AI による「なぜ間違えたか」の説明(答えは書かない)。
- 単元の積み上げの先にあるプロジェクト(総合課題)と、達成の証(修了証・資格)。
- 復習の仕組み(モバイルでの短い復習)と、学習と並行して引けるリファレンス(Docs)。

真似しない点:
- プログラミング固有のもの(実行環境、言語別パス)。
- XP・リーダーボードなどのゲーミフィケーションへの偏重。動機づけは「会社が育つ」「かたちが読めるようになる」という内発的なものを先に試す。
- 課金のための機能分割。初期は全機能無料で、価値の検証を優先する(要件 5 章)。

## 4. 会計ならではの学び方(差別化の中核)

プログラミング IDE の道具を、ひとつずつ会計に翻訳する。既存の会計教材には無く、会計 IDE だからできる学び方。

| 学び方 | プログラミングの比喩 | 会計 IDE での体験 | 状態 |
|---|---|---|---|
| 記帳して実行 | コードを書いて実行 | 仕訳を記帳すると財務諸表が動く | 実装済み |
| 予想してから実行 | テスト駆動 | 5 要素の動きを予想 → 記帳 → 予想と実際を比較 | 実装済み |
| 差分レビュー | git diff | 記帳前後の財務諸表の差分。あなたの仕訳 vs 期待される影響 | 実装済み |
| 履歴をさかのぼる | git log / undo | 帳簿を 1 件ずつ巻き戻して、会社の姿の変化を追う | 実装済み |
| 条件を変える | パラメータ・設定 | 耐用年数や金額をスライダーで動かし、結果をその場で見る | 実装済み |
| バグ探し | デバッガ | 帳簿に紛れた誤った仕訳を、財務諸表の違和感(貸借不一致、おかしな残高)から見つけて直す | 未 |
| 同じ取引、別の方法 | 同じ出力の別実装を比べる | 直接法と間接法、定額法と定率法、三分法と分記法を同じ取引で並べ、何が変わり何が変わらないかを見る | 未 |
| 分岐 | ブランチ | 「借りる」か「出資を受ける」か、「買う」か「借りる(リース)」かで、財務諸表の未来を分岐させて比べる | 未 |
| 決算をコンパイルする | ビルドパイプライン | 仕訳帳 → 総勘定元帳 → 試算表 → 決算整理 → 精算表 → 財務諸表の各段階を可視化し、途中で止めて中身を確かめる | 未 |
| 逆算 | リバースエンジニアリング | 財務諸表の変化から、どんな取引があったかを推理して仕訳を書く | 未 |
| かたちで読む | 可視化 | 比例縮尺の貸借対照表・損益計算書で会社の形を読む。「会社のかたち」はその入口 | 一部 |
| 実データで遊ぶ | OSS のコードを読む | 実在企業の決算(EDINET の XBRL)を IDE に読み込み、形を比べ、「どの会社か」を当て、何が起きたかを考える | 未 |
| 自分の会社を育てる | 個人プロジェクト | サンドボックスで会社を開業し、1 年を運営して決算する。作った会社を共有する | 一部(ふりかえりの自由記帳) |

これらは「会計を操作対象として扱う」という一つの考え方から出ている。コンテンツの課題の種類(docs/content-model.md 2 章)に順次追加する。

## 5. 対象ユーザーの広がり

| 段階 | 対象 | 求めるもの |
|---|---|---|
| いま | 日商簿記 3 級・2 級の独学者。動画やテキストで挫折した人 | 仕訳が「分かる」実感、合格 |
| 次 | 合格後の実務者、経理配属の新人、副業・フリーランス | 実務の疑問を自分で解く力、決算書を読む力 |
| 将来 | 1 級・公認会計士・税理士の受験者 | 会計基準と理論の体系的理解 |
| 将来 | 企業研修(B2B)、学校 | 受講管理、進捗の見える化 |

## 6. 現状とのギャップ

| 領域 | 最終像 | 現状(2026-11-07) | ギャップ |
|---|---|---|---|
| 学習体験(IDE) | 4 章の学び方がすべて揃い、取引の流れがアニメーションで見える。T 勘定・決算パイプラインが操作できる | 3 ペイン、6 種のステップ、差分・履歴・what-if。アニメーションは行の強調のみ | 大 |
| コンテンツ | 3 級 50 単元 → 2 級 → 1 級・実務。総合課題と模擬試験 | 3 単元(28 ステップ)。執筆と検査の仕組みはある | 大 |
| 知識の構造 | 概念マップで全体像と自分の位置が見える | テーマ・概念・用語集・パスの構造はある。マップは無い | 中 |
| 誤解への対応 | 習熟度と誤解の履歴に応じた介入(立ち止まり)。全学習者の集計でコンテンツを改善 | 誤答パターンで誤解を検出し説明。介入と集計は無い | 中 |
| 復習と定着 | 間隔反復の復習キュー。短時間の復習(モバイル) | 無い | 大 |
| 学習者と進捗 | 本登録、デバイス間同期、ダッシュボード、修了証 | 匿名ユーザーの進捗と途中再開 | 中 |
| 詰まったときの支援 | ヒント → 解答 → AI が「なぜ」を説明 | ヒント → 解答 | 中 |
| 評価 | CBT 形式の模擬試験、総合問題 | 無い | 中 |
| UI/UX | 一貫したデザインシステム、イラスト・図解、ダークモード、最初の 2 分のオンボーディング | 配色と記号の統一、アクセシビリティ対応。図解・オンボーディングは無い | 中 |
| 実データ・サンドボックス | 実在企業の決算を読む。自分の会社を育てて共有 | ふりかえりの自由記帳のみ | 大 |
| 運用 | 公開 URL、CI、監視、分析、プライバシーポリシー | ローカルのみ。ホスティング未決、CI 無し | 中 |
| 事業 | 無料枠を維持した料金プラン、B2B | 全無料。設計上の準備のみ | 小(当面不要) |

## 7. 成功の定義

学習の指標(回答ログから計算):
- 予想(predict)の初回正答率の推移。単元が進むほど上がれば、原理の理解が積み上がっている。
- 同じ誤解の再発率。解きほぐした後に下がっているか。
- 単元の完走率と、パスの完走率。
- 合格報告と、合格後の再訪(用語集・サンドボックス・実データの利用)。

製品の指標:
- β テスターの「理解できた」実感(自由記述と理解度チェック)。
- 週あたりの再訪率。
