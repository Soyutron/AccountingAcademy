# 0009. 試験範囲外のコンテンツ(歴史・不正会計)は、専用の分野と目的別パスで持ち、別の器を作らない

日付: 2026-11-13
状態: 採用(ユーザー決定2026-11-13)。実装は`docs/content-model.md` 7章と`docs/ide-design.md` 11章

## 背景
要件(`docs/requirements.md`)は「試験対策サイトではない」とし、ビジョン(`docs/vision.md`)は会計の本質、つまり「なぜ存在するか」の理解を原則に置いている。
現状のコンテンツは日商簿記3級の範囲に沿った単元だけで、会計のしくみがなぜ生まれ、どう発展したかを学ぶ単元は無い。
ユーザーは、歴史(簿記の誕生から産業の発展、企業組織の変化、グローバル化まで)と、不正会計(帳簿や財務諸表に潜む問題の発見)を、試験の枠と独立した学習体験として加える方針を決めた。業界別の会計は、実務者の保守者が加わるまで作らない。

考慮した点:
- 歴史は単元の「なぜ存在するか」と同じ役割を持つ。減価償却は鉄道会社の配当の問題から、借方・貸方は中世イタリアの人名勘定から生まれた。既存単元の導入にも、独立した単元にも使える。
- 開発方針4(`docs/roadmap.md`)は「操作して結果を見る」形を求める。歴史は読み物になりやすい。
- 既存のビルド検査(未説明の用語の禁止、`introduces`の一意性)は、内容の重複を機械的に防ぐ。
- 歴史と不正は事実の正確さがコンテンツの信頼を左右する。通説の誤り(「パチョーリが複式簿記を発明した」)や、実在企業への推測をAIの下書きが持ち込みやすい。
- 会計IDEの右ペイン、勘定科目マスタ、通貨表示は現代の日本の会社を前提にしている。

## 決定
1. **置き場。** 歴史の単元は分野`history`(会計の歴史)に置き、テーマは時代ごとに作る(複式簿記の誕生と発展 / 株式会社と鉄道 / 工場と原価計算 / 企業集団と連結 / グローバル化と基準)。歴史固有の概念(覚え書き、人名勘定、口別計算など)は`content/concepts/history.yaml`に置き、現代の概念と`related` / `contrasts`でつなぐ。既存テーマの単元の導入に史実を書く第1層は、歴史単元への参照を添えて続ける。
2. **不正会計の置き場。** 分野`forensics`(不正会計)に置き、歴史パスの時系列には混ぜない。テーマは手口の種類で分ける(架空の売上、架空の在庫、費用の資産化、循環取引)。初期は架空の事例だけで、実在企業の単元は第三者委員会の調査報告書など公開資料を出典に持つものに限り、報告書が認定した事実と単元の推測を本文で分ける。
3. **パス。** 「会計の歴史パス」を目的別パスとして持つ。パスの`exam`を任意にし、代わりに`era`(時代順の説明)を持てるようにする。歴史パスの最初の節に`bookkeeping-basics/five-elements`を置き、現代の5要素と借方・貸方を知ってから過去に戻る。歴史単元が複式簿記を前提ゼロで教え直す形は、`five-elements`との重複になるので採らない。
4. **操作の必須条件。** 単元のfrontmatterに`kind`(`lesson` | `history` | `forensics`。既定は`lesson`)を持たせる。`lesson`は従来どおりpostかpredictが1つ以上。`history`と`forensics`は「種類を問わずtaskが1つ以上」とし、読み物化の歯止めは残す。パス側ではなく単元側で持つのは、パス未所属の単元で検査が抜けないようにするため。
5. **出典。** 単元のfrontmatterに`sources`(任意)を足し、`kind`が`history`と`forensics`の単元では必須にする。ビジョン7.1の「深さ3〜4は出典必須」も同じ項目で実装する。歴史単元のレビューでは、年号・人名・帳簿名を一次資料か通史で照合したことを確認する。
6. **時期。** 「複式簿記の誕生と発展」の3単元と、それに要るIDEの拡張(シナリオ固有の勘定科目、通貨、帳簿ペインの時代表示、classifyの一般化)をM3の最初の項目にする。単元2のdebug課題がM3の「バグ探し」の最初の実験を兼ねる。不正会計の架空事例1単元もM3で作る。歴史パスの残りのテーマと不正会計の量産は、3級パスの完成(M4)より後に置く。
7. **業界別。** いまは作らない。実務者の保守者を迎えるM5〜M6で、業界単元のテンプレートと小売業の1例から始める。製造業は2級の工業簿記と一体で考える。

## 検討した代替
- 歴史単元を既存テーマの中に置く(減価償却の誕生をdepreciationテーマに): 概念との結びつきは強いが、時代順の体験が各テーマに散り、歴史パスの中でしか全体が見えない。独立した学習体験を重視して採らない。既存テーマの導入に史実を書くことで、結びつきは保つ。
- 歴史を記事(ビジョン5章の「個人の声」の器)として書く: 記事はM6以降で、査読が軽い。歴史は教材として査読されるべき内容なので、単元として持つ。
- 歴史単元にも仕訳操作を必須にする: 複式簿記以前の商人には仕訳が無い。「複式の発見」の瞬間に初めて仕訳が登場する流れそのものが追体験なので、課題の種類は学習目的で選ぶ。
- 実在企業の不正を最初から扱う: 事実の確認と表現の責任が重い。架空の事例でdebug課題と表現の方法を固めてから広げる。

## 影響
- `docs/content-model.md`: 1.1の分野に歴史と不正会計を足し、7章(試験範囲外の単元)で`kind`、`sources`、シナリオの`era` / `currency` / `view` / `accounts`、classifyの`labels` / `items`、パスの`era`を定める。ビルド検査を1つ増やし(`kind`ごとのtask条件、`sources`の必須)、1つ緩める(postかpredictの必須は`lesson`だけ)。
- `docs/ide-design.md`: 3章の表にdebugとclassifyの一般化を足し、11章で帳簿ペインの時代表示と通貨を定める。
- `docs/roadmap.md`: M3に歴史テーマの最初の3単元と不正会計の架空1単元を足す。
- `content/`: 分野`history`、テーマ`birth-of-double-entry`、パス`accounting-history`、歴史固有の誤解IDを追加する。
- E2Eの自動解答とMonkeyのオラクル(`scripts/monkey/session.mjs`)は、新しい課題の形(labels付きclassify、debug)に対応させる。
- ADR 0002は変えない。知識の正本はテーマ軸のままで、歴史パスは単元の順序付き参照にすぎない。
- ADR 0007は変えない。史実は著作物ではないが、通史や解説書の文章は転記しない。パチョーリ『スンマ』(1494年)はパブリックドメイン。
