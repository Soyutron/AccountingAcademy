# 0007. オープンソースを基本方針とし、コードとコンテンツを別のライセンスで公開する

日付: 2026-11-08
状態: 採用(ユーザー決定2026-11-08。正式名称は2026-11-14に「Open簿記」と決定。リポジトリは同日にpublicの`openboki/openboki`へ移管)

## 背景
ビジョンv2(`docs/vision.md`)は「日本の会計教育に、オープンソースの文化を」を北極星とし、教材を特定の個人や企業ではなくコミュニティが育てる共有財産にする。
現状はリポジトリがprivate、LICENSEが無く、サービス名は仮名。外部の貢献を一度でも受け入れると、ライセンスの変更には貢献者全員の同意が要る。
したがって公開前に、コードとコンテンツのライセンス、貢献の権利処理、名前の扱いを決める必要がある。

考慮した点:
- 教材(解説・演習・概念・誤解)はコードと性質が違う。ソフトウェアのライセンスは文章には向かず、Creative Commonsが標準。
- 「特定の企業だけのものにしない」という原則を守る中心はコンテンツのライセンスである。コードを閉じて持ち出されても、教材が開いていれば共有財産は保たれる。
- 学校・企業・実務家が授業や研修(有償を含む)で使えることは、普及のために望ましい。
- 会計士・税理士・教員からの貢献を受けるには、権利処理を簡単にする必要がある。

## 決定(案)
- **コード**: Apache License 2.0。特許条項があり、企業や学校が自前ホストしやすい。
- **コンテンツ**(`content/`以下と図解の定義): Creative Commons表示 - 継承4.0国際(CC BY-SA 4.0)。商用利用は許し、改変物は同じ条件で開くことを求める。Wikipediaと同じ条件なので相互利用しやすい。
- **貢献の権利処理**: Developer Certificate of Origin(DCO)。コミットの`Signed-off-by`で「自分に権利があり、プロジェクトのライセンスで提供する」ことを示す。CLA(著作権の譲渡や独占的な再許諾)は置かない。これにより運営者も他の貢献者と同じ条件に縛られ、後から閉じることはできなくなる。これはビジョンの原則どおりである。
- **名前とロゴ**: 商標として扱い、ライセンスの対象外にする。フォークは自由だが、同じ名前でサービスを名乗ることは認めない。正式名称は「Open簿記」(読みは「オープン簿記」、英字表記OpenBoki、識別子とドメインは`openboki`。2026-11-14決定)。
- **禁止事項**(CONTRIBUTINGとPRテンプレートに明記): 日商簿記の過去問・公式問題の転載、教科書・問題集からの転記、いらすとや等の再配布できない素材、AI生成画像。
- **公開時期**: M1の検証が終わり名称が決まった時点でリポジトリをpublicにする(M2)。機能の完成を待たない。
- **学習者のデータ**: 回答・進捗の個票は公開しない。公開するのは匿名化した集計値(つまずきマップ)だけ。

## 検討した代替
- コードをMITにする: 最も単純。Apache 2.0との差は特許条項とNOTICEの扱いだけで、どちらでもよい。企業の採用しやすさでApache 2.0を推す。
- コードをAGPL-3.0にする: 改変したSaaSの公開を強制でき、「閉じた有料フォーク」を防げる。ただし共有財産の中心はコンテンツで、CC BY-SAが同じ役割を果たす。コードまで強いコピーレフトにすると、学校・企業が改変して使う際の心理的な障壁になる。閉じたフォークを強く防ぎたい場合の選択肢として残す。
- コンテンツをCC BY-NC-SA(非営利)にする: 有料の講座や研修での利用を止められるが、実務家が自分のセミナーや社内研修で使う道も塞ぐ。「非営利」の境界が曖昧で、学校(私立)や自治体でも判断に迷う。Wikipediaとも互換がない。採らない。
- コンテンツをCC BY(継承なし)にする: 最も自由だが、改変した教材を閉じて配布できるため「共有財産にする」原則に反する。採らない。
- CLAを置いて運営者だけが再許諾できるようにする: 将来の収益化の選択肢は残るが、貢献者と運営者が対等でなくなり、オープンソースの文化という理念と矛盾する。採らない。
- 公開を3級が揃うM4まで待つ: 見栄えはよくなるが、M2〜M3の間に外部の目(誤りの指摘、環境構築の躓き)を失う。OSSは早く開く方が得る物が多い。採らない。

## 影響
- `docs/requirements.md` 5章(料金体系)を「全コンテンツ無料を恒久的な方針とし、収益化を目標にしない」に改める。
- ADR 0004(視覚方針)の「いらすとやを使わない」理由に「CC BY-SAのコンテンツに同梱して再配布できない」が加わる。結論は変わらない。
- ADR 0005(CI方針)の「privateリポジトリ」の前提が外れる。publicではGitHub Actionsの分数が無料になるが、ローカル正の方針は変えない。
- ADR 0006(ホスティング)の「商用化の制約を持たない」は、学校・企業が自前ホストできるDocker構成として引き続き意味を持つ。Docker Composeの手順をM7までに文書化する。
- 追加する成果物(M2): `LICENSE`(Apache 2.0)、`content/LICENSE`(CC BY-SA 4.0)とREADMEのライセンス節、`CONTRIBUTING.md`、`CODE_OF_CONDUCT.md`(Contributor Covenant日本語訳)、Issue / PRテンプレート、DCOの案内と検査、プライバシーポリシー。
- Supabaseの匿名ユーザーに関する運用(90日削除、RLS)は公開後も変えない。
