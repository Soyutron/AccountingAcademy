# 要件定義(v0.6)

更新日: 2026-11-08
状態: ユーザーの構想(2026-11-07)を反映。**[確定]** はユーザーの方針として確定、**[仮]** は提案中で「未決事項」で判断を仰ぐ。

## 1. サービスコンセプト **[確定]**

**会計を基礎から専門領域まで、原理・概念・構造の理解を軸に体系的に学べる長期的な知識基盤。**

- 誰もが無料で学べ、教材はオープンライセンスの共有財産として、学習者・実務家・専門家が共同で育てる(ビジョン v2、ADR 0007)。学習体験の洗練を先に、コミュニティ機能は利用者が付いてから段階的に入れる(`docs/roadmap.md`)。

- 試験対策サイトではない。資格合格は学習の成果の一つと位置づけ、合格後も実務の疑問や高度な理論の学習に使い続けられることを目指す。
- 学習体験は **会計 IDE**(`docs/ide-design.md`)。Codecademy の学習画面のように、ガイド(短い物語と課題)・ワークスペース(仕訳帳)・結果(貸借対照表と損益計算書)を
  1 画面に置き、仕訳を「記帳」すると財務諸表がその場で動く。長い解説を読んでから問題を解く形は取らない。
- 四択ではなく操作で学ぶ。仕訳を組み立てる、動きを予想してから実行する、条件を変えて影響を見る、科目を箱に分ける。
- 誤りは「不正解」で終わらせず、学習者の仕訳の影響と期待される影響を並べて、何がどう違うかを見せる。

### 教育方針(解説と演習の設計原則)
仕訳を例に、各単元で次の 5 点を必ず扱う。
1. 勘定科目が 5 要素(資産・負債・純資産・収益・費用)のどれに属するか
2. なぜその要素に属するのか
3. 取引で資産・負債・純資産がどう変化するか
4. 仕訳が財務諸表(貸借対照表・損益計算書)にどう影響するか
5. その会計処理が必要とされる理由・背景にある考え方

暗記ではなく原理の理解によって、未知の取引や複雑な論点に対応できる力を養う。
概念同士のつながりを可視化し、断片ではなく相互に接続された体系として理解させる。

### 専門用語の扱い **[確定]**
学習者が専門用語をすでに知っていることを前提にしない。初学者が無理なく読め、上級者は深く掘れることを両立する。
- **初出時の説明**: 専門用語が単元に初めて登場するときは、本文で平易に定義し、具体例を添える。既習の知識との関連も示す。
- **インタラクティブな用語解説**: 本文中の専門用語にカーソルを合わせる、またはクリック / タップすると、その場で簡潔な説明が出る。学習の流れを止めない。
- **段階的な理解**: 一文の定義 → 具体例つきの短い解説 → 詳しい解説(単元)へと、必要な深さまで掘り下げられる。
- **用語間の関連付け**: 用語から関連する概念や前提知識へ辿れる。
- **用語集との連携**: 登場した用語は用語集に集約され、いつでも検索・復習できる。

用語は暗記の対象ではなく、「なぜ必要か、何を意味するか、他の概念とどうつながるか」を理解する入口として扱う。

## 3. 学習コンテンツの構造 **[確定]**

資格試験の範囲や難易度で知識を分断せず、会計の概念・原理を中心に体系化し、資格別コースはそこから必要な部分を参照する。
二つの軸を持つ。

- **テーマ軸(知識の正本)**: 「現金・預金」「減価償却」「連結会計」などのテーマごとに、入門から専門まで深さ順に単元を積む。
  単元は概念(原理・用語・処理)に紐づき、概念同士は「前提」「関連」「対比」の関係でつながる(概念マップ)。
- **パス軸(目的別の参照)**: 「簿記 3 級合格パス」「簿記 2 級合格パス」などは、テーマ軸の単元を選んで並べたもの。
  試験固有の情報(出題形式、配点、時間、範囲表)はパスにだけ持ち、テーマ軸には持ち込まない。

詳細な構造・記述形式・演習の種類は `docs/content-model.md` で定義する。

## 4. 主要機能

### 4.1 学習(コア)
| 機能 | 内容 | MVP |
|---|---|---|
| テーマ閲覧 | 分野 → テーマ → 単元(深さ順)の閲覧 | ○ |
| 学習パス | 資格別に単元を順に辿る。進捗率表示 | ○(3 級パス) |
| 会計 IDE | ガイド / ワークスペース / 結果の 3 ペイン。ステップ型の単元(observe / post / predict / tweak / classify / calc)を進める(→ ide-design.md) | ○ |
| 仕訳帳 | 仕訳を組み立てて記帳。入力中に 5 要素と当期純利益への影響を表示。記帳済みの仕訳が帳簿として積まれる | ○ |
| 財務諸表のリアルタイム更新 | 記帳のたびに貸借対照表と損益計算書が更新され、変わった行と差分を強調 | ○ |
| 条件を変える | 金額・耐用年数などをスライダーで変え、計算結果の変化を見る(what-if) | ○ |
| 誤解の検出と誘導 | 誤答から「どの誤解か」を判定し、その誤解に応じたフィードバックと、解きほぐす単元への導線を出す。同じ誤解が続いたら短い立ち止まりを挟む(→ architecture.md 6 章) | ○ |
| 概念マップ | 概念の前提・関連・対比をグラフで可視化。学習済み / 未学習を色分け | ○(テーマ単位の簡易版) |
| 用語ポップオーバー | 本文中の専門用語にホバー / タップで一文の定義と具体例を表示。そこから用語集・単元へ辿れる | ○ |
| 用語集 | 登場した専門用語と勘定科目を検索・一覧できる。各用語から定義 → 具体例 → 詳しい解説(単元)へ段階的に掘れる。学習者が出会った用語を復習用に絞り込める | ○ |
| 総合問題 | 決算整理から財務諸表までの通し問題 | 後 |
| 模擬試験 | CBT と同じ時間・構成(パス固有) | 後 |
| 帳簿・精算表エディタ | 転記、精算表の一括採点 | 後 |
| AI 解説 | 誤答理由の説明、質問回答 | 後(未決) |

### 4.2 学習者とデータ **[確定]**
- ログインは必須にしない。ゲストのまま全コンテンツを学習できる。
- アカウント登録・ログインも提供する。進捗の保存、履歴、デバイス間同期は将来の機能だが、設計段階で対応できるようにする。
- ゲストで学習を始め、後からアカウントを作ると、それまでの学習データを引き継げる。

設計上の含意(決定 2026-11-07、architecture.md 3.2 / 5 章):
- ゲストは Supabase の匿名ユーザーとして扱い、最初の回答時に匿名サインインする。回答・進捗は MVP から DB に保存する。
- 本登録は匿名ユーザーの昇格(メール追加 / Google 連携)。ID が変わらないので履歴は自動的に引き継がれる。
- 匿名ユーザーは最終活動から 90 日で削除する。

MVP は匿名ユーザーのみ。本登録(メール / Google)はフェーズ 7。 **[確定]**

### 4.3 対象外(当面作らない)
- 法人管理(チーム、受講管理)、決済、ネイティブアプリ。
- コミュニティ機能(報告・改善の導線、Q&A、記事、コンテスト)は作らないのではなく、`docs/roadmap.md` の段階と開始条件に従って順に入れる。先回りして作らない。

## 5. 料金体系・開発体制 **[確定]**
- 全コンテンツ・全機能を無料で提供する。これは恒久的な方針で、収益化を目標にしない。決済機能は作らない。運営費(VPS、AI の利用料)は利用者が付いた段階で寄付・スポンサーで賄えるか検討する(roadmap M7)。
- コードとコンテンツはオープンライセンスで公開する(ADR 0007)。
- 個人開発で始め、引き継げる形を保つ。MVP までの期間・予算に明確な上限は設けない。
- ただし最初から全部作らず、**教育的価値を検証できる最小限**から段階的に拡張する(→ 6 章)。

## 6. MVP の範囲と検証 **[仮]**

MVP の目的: 「原理理解を軸にした学習体験は、従来の暗記型より深い理解につながるか」を検証する。

### 6.1 範囲
- コンテンツ: 3 級の全範囲をテーマ軸で構成した単元(深さ 1〜2)+ 3 級合格パス。
  加えて 2〜3 テーマ(例: 減価償却、貸倒引当金、商品売買)だけ深さ 3(2 級相当)まで用意し、「テーマを深く掘る」体験と構造の妥当性を確かめる。
- 機能: 4.1 の MVP ○ 印。ゲストのみ、ブラウザ保存。
- 技術: 7 章の方向性。

### 6.2 検証方法
- テスター 10 名程度(簿記未学習〜3 級学習中)に 2 週間使ってもらう。
- 計測: 単元の完了率、演習種別ごとの初回正答率(特に「理由」「財務諸表への影響」の問題と「仕訳」の問題の差)、
  使用後の理解度チェック(初見の取引について要素の増減と仕訳を答えられるか)、自由記述の感想。
- 判断: 「仕訳は切れるが理由や影響を答えられない」が多ければ解説・演習の設計を見直す。

## 7. 技術アーキテクチャ **[確定]**(ADR 0003、`docs/architecture.md`)

- Next.js(App Router、標準出力)+ Supabase(Auth と 2 テーブル)を MVP から使う。
- 採点と解説はコンテンツだけで完結(DB 不要)。コンテンツはリポジトリで管理し、ビルド時に検査する。
- 学習者の回答・進捗は匿名ユーザーの時点から DB に残し、誤解の検出とコンテンツ改善に使う。
- ホスティングは未決。特定ホストの固有機能に依存しない。

## 8. 非機能要件 **[仮]**
- PC とスマートフォンのブラウザ(レスポンシブ)。仕訳エディタはキーボードだけで操作完了できること。
- 日本語のみ。
- 匿名ユーザーの回答データも行動履歴なので、β 開始時点でプライバシーポリシーを置く。本登録導入時にメールアドレスを扱うため個人情報保護法への対応を整備する。
- 日商簿記の過去問・公式問題は転載しない。演習はすべて自作する。

## 9. 成功指標 **[仮]**
- MVP: 6.2 の検証指標。
- 公開後: 単元完了数、パス完走率、再訪率(合格後も使われているか)、理解度チェックの正答率。
