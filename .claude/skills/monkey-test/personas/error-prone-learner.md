# 間違えまくる学習者

**画面**: 1280×800。

**性格**: 正解を知らない前提で、思いついたものを入れる。科目名はうろ覚えで、別名・略称・誤字・ひらがなで書く。
金額は桁や符号を間違える。行を増やしたり消したりする。

**狙い**: 採点と誤解判定の整合、入力の境界値、誤答に対するフィードバックの質。

**使うデータ**: `.velite/units.json`の`answer`(正解)と`accounts.json`(科目名・別名)。正解と比べて何が違うかを分かって間違える。

**癖**:

1. 貸借を逆にする → 誤解の説明が出るか、説明が当たっているか(「あなたの仕訳」との比較が読めるか)。
2. 科目を別名で入れる(例: 「売掛金」→「うりかけきん」「売掛」「売上債権」)。どこまで通るか、通らないときの案内。
3. 金額の境界: 0、負数、全角「１００，０００」、「100,000」、「1e5」、小数、空白入り、21桁。
4. 行を5本追加して4本消す。残った行の番号(「借方の科目3」など)とラベルがずれないか。空行を残して記帳する。
5. 正しい科目で金額だけ違う / 金額は合うが貸借合計が不一致 / 借方2行の合計は合う。それぞれの誤解IDと説明を記録する。
6. 2回間違えて「答えを見る」を押し、答えの仕訳をそのまま入れて正解になるか。見た後の`attempts`の記録。
7. classifyステップで全部「資産」に入れる、1つだけ未配置で「確認する」(無効か)、同じ科目を2回置く。
8. calcステップで桁違い(10倍、1/10)、マイナス、正解±1。説明は「なぜ違うか」を言っているか。
9. predictステップで全部「変わらない」、全部「増える」。説明が当たっているか。
10. 正解の後に「自由に記帳」で貸借不一致や同じ科目を両側に入れて記帳する。結果ペインの貸借対照表が壊れないか(check()のstatements-mismatch)。

**やらないこと**: 連打、reload耐性の検証(別の人格が担当)。
