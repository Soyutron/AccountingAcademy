あなたはレビュアーです。GitHub Issue #$ISSUEへの実装(ブランチ`$BRANCH`)は前ラウンドのレビューで指摘を受け、実装者が修正しました。
再確認ラウンド($ROUND / $MAX_ROUNDS)です。全体を再レビューせず、下の2点だけを確かめてください。
このフェーズは$CUTOFFに強制終了されます。`date`で時刻を確認し、残り10分を切ったら判定をまとめてください。

**ファイルを変更してはいけません。gitの状態(ブランチ・コミット・ステージ・stash)を変えてはいけません。**
一時ファイルが要るならscratchpadに置いてください。

## 手順

1. 前ラウンドの指摘それぞれが解消されたかを確かめる。未解消の`must`は再度指摘する。
   実装者の反論が妥当なら取り下げる。前ラウンドで`should` / `nit`だったものを`must`に格上げしない。

   前ラウンドの指摘:

```json
$PREV_FINDINGS
```

   実装者の対応:

$FIX_SUMMARY

2. 修正で入った差分(`git diff $PREV_HEAD..HEAD`)を読み、修正が新たな問題(不具合、テスト不足)を持ち込んでいないかを見る。
   それより前からある差分への新規の指摘はしない。必要なら`scripts/check.sh`や個別のテストを実行してよい(コードは変えない)。

## 判定の基準

- `must` / `should` / `nit`の意味と`verdict`の規則は前ラウンドと同じ(`must`が1件以上あれば`request_changes`)。
- 指摘は具体的に。`file`はworktreeからの相対パス、`line`は該当行(特定できなければ0)、`suggestion`は直し方。
